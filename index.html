DETERMINISTIC TEETH

Consequences stay on-chain.

  • creator-only grant submission
  • resource-local permanent history
  • LOCKED rejects later grants pre-inference
  • holder-only release
  • new exclusivity forbidden after prior history
REVIEWER PATH

Prove both semantics and enforcement.

Use your own funded StudioNet wallets. No wallet is hardcoded into the app.

  1. 01
    Create a fresh resource

    Connect a creator wallet, load the example and create the resource. Confirm OPEN and grant_count 0.

  2. 02
    Submit exclusive text

    Set a grantee wallet you control, load Exclusive example, submit and expect EXCLUSIVE_GRANT → LOCKED.

  3. 03
    Prove the lock has teeth

    As creator, try another grant on the locked resource. Expect FINISHED_WITH_ERROR: Resource is locked by an exclusive grant.

  4. 04
    Release as holder

    Switch to the recorded holder wallet, release exclusivity and verify OPEN while historical grant_count remains 1.

  5. 05
    Run the negative control

    Create a separate resource and submit the Non-exclusive control. Expect NON_EXCLUSIVE_GRANT → OPEN.
